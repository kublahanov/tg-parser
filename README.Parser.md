# Описательный алгоритм работы парсера

Если у чата не истинен флаг полной загрузки старых сообщений (is_old_uploaded == false):

1. Загрузка старых сообщений:

    Проверяем, есть ли сообщения у выбранного чата.

    1.1. Если сообщений нет - загружаем все, начиная от самого нового:
        Загружаем первые 100 сообщений со сдвигом 0:
        /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=0

        Сохраняем значение count из первого запроса. Например count = 1927.

        Далее прибавляем к сдвигу 100 на каждом цикле:
        /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=100
        /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=200
        ...

        Нужно двигаться на увеличение параметра add_offset до тех пор, пока оно не станет больше значения count сохранённого на первом шаге.
        В этом случае - заканчиваем цикл.
        Например для count = 1927, заключительным будет запрос:
        /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=1900&max_id=2032

        Ставим чату флаг - is_old_uploaded = true.

    1.2. Если сообщения есть (т. е. чат "недогрузился", возможно из-за ошибки) - продолжаем загрузку от самого старого сообщения:

        Ищем минимальный ID сообщения среди загруженных.
        Например это ID = 2032.

        Загружаем первые 100 сообщений со сдвигом 0:
        /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=0&max_id=2032

        Сохраняем значение count из первого запроса.
        Например count = 1927.

        Далее прибавляем к сдвигу 100 на каждом цикле:
        /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=100&max_id=2032
        /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=200&max_id=2032
        ...

        Здесь логика противоположная той, что была в предыдущем пункте.
        Сначала один или несколько циклов подряд количество сообщений может быть равно нулю.
        Нужно двигаться на увеличение параметра add_offset до тех пор, пока оно не станет больше значения count сохранённого на первом шаге.
        В этом случае - заканчиваем цикл.
        Например для count = 1927, заключительным будет запрос:
        /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=1900&max_id=2032

        После загрузки старых сообщений, или если истинен флаг полной загрузки старых сообщений (is_old_uploaded == true):

2. Загрузка новых сообщений (если у чата is_old_uploaded == true):

    Ищем максимальный ID сообщения среди загруженных.
    Например это ID = 2132.

    Загружаем первые 100 сообщений со сдвигом 0:
    /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=0&min_id=2132

    Далее прибавляем к сдвигу 100 на каждом цикле:
    /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=100
    /api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=200
    ...

    Заканчиваем цикл тогда, когда количество сообщений будет равно нулю.
