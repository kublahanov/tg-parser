# Алгоритм работы парсера

Алгоритм составлен на базе описания АПИ Telegram: https://core.telegram.org/api/offsets.

### 1. Предварительный шаг:

Проверяем общее число сообщений у выбранного чата:
- `/api/messages.getHistory?peer=-1001432413295&limit=1&add_offset=0`

Сохраняем значение **count** из этого запроса. Например, **count** = 1927.

Если АПИ вернуло нулевое число сообщений (общее) - значит чат ещё пуст, 
и загрузка окончена.

### 2. Загрузка старых сообщений:

Выполняется, если у чата не истинен флаг полной загрузки старых сообщений (**is_old_uploaded** == false).

Проверяем, есть ли сообщения у выбранного чата.

#### 2.1. Если сообщений нет - загружаем все, начиная с самого нового:
        
Загружаем первые **100** сообщений со сдвигом **0**:
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=0`

Далее прибавляем к сдвигу **100** на каждом цикле:
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=100`
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=200`
- `...`

Нужно увеличивать параметр **add_offset** до тех пор, пока он не станет больше значения **count**, сохранённого на предварительном шаге, либо до тех пор, пока количество возвращённых сообщений не станет равно нулю. В обоих случаях - заканчиваем цикл.

Например, для **count** = 1927, заключительным будет запрос:
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=1900`

Ставим чату флаг - **is_old_uploaded** = true.

#### 2.2. Если сообщения есть (т. е. чат "недогрузился" - возможно из-за ошибки) - продолжаем загрузку от самого старого сообщения:

Ищем минимальный **ID** сообщения среди загруженных. Например, это **ID** = 2032.

Загружаем первые **100** сообщений со сдвигом **0**:
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=0&max_id=2032`

Далее прибавляем к сдвигу **100** на каждом цикле:
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=100&max_id=2032`
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=200&max_id=2032`
- `...`

Здесь логика - отличается от той, что была в предыдущем пункте.
Сначала один или несколько циклов подряд количество сообщений может быть равно нулю.

Нужно увеличивать параметр **add_offset** до тех пор, пока он не станет больше значения **count** сохранённого на предварительном шаге. В этом случае - заканчиваем цикл.

Например, для **count** = 1927, заключительным будет запрос:
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=1900&max_id=2032`

### 3. Загрузка новых сообщений:

Выполняется, если истинен флаг полной загрузки старых сообщений (**is_old_uploaded** == true).

Ищем максимальный **ID** сообщения среди загруженных. Например, это **ID** = 2132.

Загружаем первые **100** сообщений со сдвигом **0**:
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=0&min_id=2132`

Далее прибавляем к сдвигу **100** на каждом цикле:
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=100&min_id=2132`
- `/api/messages.getHistory?peer=-1001432413295&limit=100&add_offset=200&min_id=2132`
- `...`

Нужно увеличивать параметр **add_offset** до тех пор, пока он не станет больше значения **count**, сохранённого на предварительном шаге, либо до тех пор, пока количество возвращённых сообщений не станет равно нулю. В обоих случаях - заканчиваем цикл.
